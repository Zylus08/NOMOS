### Executive Summary

Milestone M5.3 introduced an isolation boundary to scrub system identities and prevent leakage from the simulator to the discovery controller. However, code inspection revealed that `nomos/pde/isolation.py` relied on Python's built-in `hash()` function (`abs(hash(field.id)) % 1000000`), which is non-cryptographic, randomized per Python process via `PYTHONHASHSEED`, and keyed on string metadata rather than physical observation tensors. Furthermore, M5.3 documentation claimed "cryptographic scrubbing" without cryptographic justification.

This audit details the full replacement of the ad-hoc hashing mechanism with deterministic SHA-256 digests over observable numerical arrays, the implementation of an explicit allowlist schema for observation serialization, and the correction of all manuscript and report claims.

---

### 1. Forensic Inspection of M5.3 Isolation

In M5.3, `create_learner_field_observation()` contained:
```python
blind_id = f"blind_system_{abs(hash(field.id)) % 1000000:06d}"
obs = SpatiotemporalField(
    id=f"learner_obs_{field.id}",
    pde_name=blind_id,
    ...
)
```

#### Defect 1: Process-Dependent SipHash Randomization
Python's built-in `hash()` uses SipHash-2-4 with a randomized salt initialized per Python interpreter process (unless `PYTHONHASHSEED=0` is set externally). Consequently:
- Running an episode in Process A generated `blind_system_482910`.
- Running the identical episode in Process B generated `blind_system_819231`.
This broke cross-process identity matching and reproducible tracking of blinded benchmark systems.

#### Defect 2: String-Metadata Keying Rather Than Physical Content
`hash(field.id)` hashed the string identifier rather than the spatiotemporal observation tensor. If a simulator emitted identical physics under different `field.id` strings, the system generated disparate IDs. Conversely, if two different simulators used the same `field.id`, identical IDs were assigned.

#### Defect 3: Non-Cryptographic Modulo Truncation
Computing `abs(hash()) % 1000000` created a 6-digit integer space with a high collision probability under the birthday paradox ($\approx 50\%$ collision probability after only 1,177 observations). Calling this "cryptographic scrubbing" was scientifically inaccurate.

### 2. Cryptographic SHA-256 Allowlist Architecture

We redesigned `nomos/pde/isolation.py` around three formal invariants:

#### Invariant 1: Deterministic Tensor Byte Hashing
Opaque identifiers are generated by hashing the IEEE 754 float64 byte representations of observable spatial and temporal arrays:
```python
def compute_opaque_observation_digest(field: SpatiotemporalField) -> str:
    hasher = hashlib.sha256()
    hasher.update(str(int(field.spatial_dim)).encode("ascii"))
    for ch in sorted(field.channel_names):
        hasher.update(ch.encode("utf-8"))
    hasher.update(np.ascontiguousarray(field.x, dtype=np.float64).tobytes())
    if field.y is not None:
        hasher.update(np.ascontiguousarray(field.y, dtype=np.float64).tobytes())
    hasher.update(np.ascontiguousarray(field.t, dtype=np.float64).tobytes())
    hasher.update(np.ascontiguousarray(field.u, dtype=np.float64).tobytes())
    return hasher.hexdigest()
```
The opaque system identifier is derived strictly as:
$$\text{blind\_id} = \text{"blind\_system\_"} + \text{SHA256}(\mathbf{X}, \mathbf{t}, \mathbf{u}, \text{channels})[:12]$$

**Properties:**
1. **Process Independence:** Invariant to Python process lifetime, interpreter version, or `PYTHONHASHSEED`.
2. **Platform Uniformity:** Byte ordering is standardized via contiguous float64 arrays.
3. **Collision Resistance:** A 12-character hexadecimal digest ($16^{12} \approx 2.8 \times 10^{14}$ states) eliminates accidental collisions across benchmarks.

#### Invariant 2: Explicit Allowlist Filtering
Rather than relying on a fragile denylist, the isolation boundary defines an explicit allowlist of permitted spatiotemporal fields:
```python
ALLOWED_OBSERVATION_ATTRIBUTES: Set[str] = {
    "id",
    "pde_name",
    "x",
    "y",
    "t",
    "u",
    "channel_names",
    "boundary_condition",
    "spatial_dim",
    "units",
    "observation_mask",
    "noise_level",
    "provenance",
}

DISALLOWED_EVALUATOR_ATTRIBUTES: Set[str] = {
    "u_clean",
    "u_t_true",
    "true_parameters",
    "_simulator",
    "simulator",
    "analytical_solution",
    "exact_coefficients",
    "governing_equation",
    "source_pde_name",
}
```
All evaluator-only fields (`u_clean`, `u_t_true`, `true_parameters`, attached simulator instances) are explicitly purged and set to `None`.

#### Invariant 3: Allowlist Serialization Boundary
`serialize_learner_observation(field)` exports exclusively allowlisted fields to serializable dictionaries, guaranteeing that no hidden simulator attributes can leak across network or IPC boundaries.
